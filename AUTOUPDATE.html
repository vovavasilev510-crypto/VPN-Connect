Автообновление VPN Connect 2.1

  1. Запустите Start.cmd. Выберите «Общая публичная подборка» и нажмите «Загрузить». Чтобы взять оформление из своей подписки, выберите «Своя ссылка» и загрузите её. Поддерживаются текстовые и Base64-подписки со ссылками на серверы.
  2. Настройте название, объявление, имена и подписи серверов. Отмеченные поля заменяются значениями редактора.
  3. На вкладке «Публикация GitHub» укажите репозиторий: например VPN-Connect (аккаунт определяется по токену) или владелец/имя для другого доступного репозитория. В поле «Файл» укажите sub, sub2, subscriptions/family.txt или другой путь. Разрешены латиница, цифры, дефис и подчёркивание; конечный файл может иметь расширение. Служебные пути зарезервированы.
  4. Введите токен с разрешениями Contents, Workflows и Actions: Read and write для выбранного репозитория. Для личного репозитория друга fine-grained токен должен быть создан самим другом. Fine-grained токены сторонних collaborators не поддерживаются GitHub для записи в чужие личные репозитории. Участник с правом Write может использовать classic-токен с public_repo и workflow. Токен вводится только в программу и не сохраняется на диск. Для создания нового личного репозитория отметьте «Создать новый публичный репозиторий, если его нет»; нужны права на создание, для fine-grained токена — Administration: Read and write и доступ к новому репозиторию. Создание выполняется в аккаунте владельца токена. Для чужого владельца используйте существующий репозиторий с доступом к записи.
  5. Отметьте разрешение замены и нажмите «Установить / обновить автоматику». Программа загрузит свежие серверы, установит файлы одним коммитом и запросит первый запуск. Проверьте статус кнопкой «Проверить обновления в GitHub Actions».

Готовую ссылку скопируйте в Happ. В ней уже объединены обе публичные подборки igareck; выбирать режим в редакторе не нужно. Оформление берётся из загруженной и отредактированной подписки, а список серверов для автоматики — из встроенных публичных источников. Своя ссылка не становится новым фоновым источником автоматически.

Несколько подписок

Для каждой подписки повторите установку с нужным именем файла и оформлением. В одном репозитории могут одновременно обновляться sub, sub2 и subscriptions/family.txt. Их шаблоны и исключения находятся в разных папках .vpn-connect/profiles. Общее расписание обновляет все установленные профили примерно каждые два часа. Компьютер и токен установки для этих запусков не нужны.

Для изменения оформления загрузите нужную подписку, отредактируйте её и повторите установку с тем же выходным путём. Для новой подписки задайте новый путь. Переименование выходного пути создаёт новый профиль, старый продолжает обновляться. Разовая публикация изменяет только результат: при следующем запуске автоматика применит сохранённый шаблон.

Совпавшие подключения сохраняют ваши имена и подписи. Новые конфигурации получают исходные названия без разделения на режимы. Исключения привязаны к точным параметрам подключения. Если ключ изменился, это считается новым сервером.

ZIP как запасной способ

Кнопка экспорта собирает пакет для указанного поля «Файл». Для ручной установки загрузите его содержимое в корень репозитория, включая .github и .vpn-connect, затем запустите Actions → Update VPN subscriptions → Run workflow. При установке кнопкой в программе ручная загрузка не требуется.

Если появляется HTTP 403

Проверьте владельца токена и выбранный репозиторий. Fine-grained токен владельца: Contents, Workflows и Actions — Read and write. Для classic-токена участника публичного репозитория: public_repo и workflow, при этом у аккаунта должен быть доступ Write. Версия 2.1 показывает ответ GitHub и запрос, на котором произошёл отказ, и различает типичные сообщения о лимите запросов и правилах ветки. Сами права аккаунта программа не меняет. Оригинальное сообщение сервера обрезается, строки токенов скрываются. Официальная документация о типах и ограничениях токенов.

Проверка и ограничения

«Запуск запрошен» означает, что GitHub принял запрос, а не что задание завершилось успешно. Политики репозитория и защита основной ветки могут запрещать Actions или запись. После создания репозитория проверьте, что токену разрешён доступ к нему. GitHub может задерживать запуски и отключать расписание в неактивном публичном репозитории; в этом случае повторная установка включает workflow.

Некорректные записи публичных источников пропускаются. При ошибке загрузки или разбора профиля задание завершается до записи результатов. Работоспособность туннелей проверяет автор публичной подборки; доступность у вашего оператора нужно проверить в Happ. При переходе с 1.9 прежняя подписка sub2 продолжает обновляться; её новый профиль имеет приоритет над старым шаблоном.
